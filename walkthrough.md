## 2026-10-21 (Headless spec runs fail instead of hanging)

- Findings: CI reached the test suite for the first time and timed out after 20 minutes. The log showed "Running database migrations" and then silence. Reproduced locally by renaming `app/mailsync.exe`: the process printed the same line and hung until killed. Cause: `Application.start()` awaits `mailsync.migrate()` before it ever looks at spec mode, and the failure path calls `dialog.showMessageBoxSync`, which blocks forever under xvfb because nothing can dismiss the dialog. The theme error handler in the same file already documents this exact hazard and skips the dialog in spec mode.
- Conclusions: A headless spec run must never open a blocking dialog. Exiting with the error keeps the failure visible in the log and turns a 20 minute timeout into a few seconds, without changing what interactive users see. The CI job still cannot run the suite at all, because the database schema is created by the engine and this fork has no linux-x64 engine artifact; that needs a separate decision about engine provisioning.
- Actions: `app/src/browser/application.ts` logs the migration error and calls `app.exit(1)` when `specMode` is set, before constructing the dialog. Verified by renaming the engine binary: the run went from hanging to `Nuntio could not run the mailsync migration: ... ENOENT` with exit code 1 in seconds; with the engine restored, the tracking-sync specs still pass (2 tests, 0 failures). Prettier, ESLint, and `tsc --noEmit` pass; validated.

## 2026-10-21 (Kleiner Windows-pakket)

- Findings: het Windows-pakket was 1,3 GB. De asar-unpack-glob pakte de hele `node-llama-cpp`-closure, en npm had alle varianten voor deze machine geïnstalleerd: `win-x64-cuda-ext` 351 MB, `win-x64-cuda` 168 MB, `win-x64-vulkan` 71 MB, `win-x64` 30 MB, `win-arm64` 11 MB. Daarnaast scheepte de build `.pdb`-symbolen mee (mailsync.pdb 21 MB). De closure-glob matchte op Windows bovendien nooit, omdat `path.relative` backslashes teruggeeft terwijl asar-globs forward slashes verwachten; de `*.dll`/`*.node`-globs hielden de binaries toch op schijf.
- Conclusions: alleen de varianten voor de doelplatform/arch meebouwen, met één versnelde laag (Vulkan op Windows/Linux, Metal op Apple silicon) en CPU als basis. CUDA vervalt: dat is 519 MB voor een acceleratie die alleen op NVIDIA-machines met de CUDA-runtime werkt, en `node-llama-cpp` valt zonder die pakketten terug op de volgende laag in plaats van te falen. Filteren op de unpack-lijst is niet genoeg; de niet-gekozen varianten moeten ook in `ignore`, anders trekt de `*.dll`-glob ze alsnog naar buiten. Debug-symbolen horen niet in een release.
- Actions: `app/build/build.js` normaliseert closure-paden naar forward slashes, kiest per platform de llama-varianten via `llamaPackagesForTarget`/`LLAMA_ACCELERATED_LAYER`, voegt de afgevallen varianten als `ignore`-regex toe en sluit `*.pdb` uit. Gemeten na rebuild: `app/dist/Mailspring-win32-x64` 1306 → 730 MB, installer 623 → 300 MB, `@node-llama-cpp` in het pakket alleen `win-x64` + `win-x64-vulkan` (147 MB i.p.v. 624 MB), geen `.pdb` meer. Gepackagede app start nog steeds (25 s, proces levend) en `mailsync.exe` zit in `app.asar.unpacked`; Prettier en `node --check` groen; validated.
